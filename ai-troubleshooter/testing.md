# IT Troubleshooting Assistant
## Software Testing Report

**Developer:** Ayden Manuel
**Course:** COSC 4272 Senior Seminar

## 1. Testing Objectives

The purpose of testing was to verify that the
IT Troubleshooting Assistant functions correctly,
handles user input, and provides appropriate
troubleshooting recommendations.

## 2. Testing Environment

- Operating System: Windows
- Browser: Google Chrome
- Hosting Platform: GitHub Pages
- Technologies: HTML, CSS, JavaScript

## 3. Functional Test Results

| Test | Expected Result | Status |
|---|---|---|
| Application loading | Homepage displays | Pass |
| Internet troubleshooting | Correct recommendations | Pass |
| Slow computer troubleshooting | Recommendations display | Pass |
| Startup troubleshooting | Recommendations display | Pass |
| Software troubleshooting | Recommendations display | Pass |
| Yes/No navigation | Correct decision path | Pass |
| Restart button | Resets troubleshooting | Pass |
| Input validation | Alerts on missing selection | Pass |
| Question indicator | Displays Question 1 | Pass |

## 4. Testing Process

The application was tested by selecting the
available troubleshooting categories and
answering diagnostic questions.

Each category was checked to verify that
appropriate recommendations appeared.

The restart functionality was also tested
to ensure users could begin another session.

The question progress indicator was tested
to confirm that Question 1 displayed correctly.

## 5. Known Limitations

- The application uses predefined diagnostic rules.
- It does not connect to a live AI model.
- It cannot automatically diagnose hardware.
- It does not store previous troubleshooting sessions.

## 6. Conclusion

Manual testing confirmed that the application's
main troubleshooting features functioned as expected.

The application provides a working foundation
for future enhancements and additional diagnostic
capabilities.
